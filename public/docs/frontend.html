Frontend Instructions

Build the school management frontend against this server. Use the stack below, keep UI in reusable components, and talk to the backend through a Vite proxy. API reference stays at /docs.

Vite + React 18.0.3 Tailwind 4.3 shadcn/ui TanStack Query Reusable components only

Vite reverse proxy

This preview exposes one port. Proxy /server to the Nest backend so the browser never calls a second origin.

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    allowedHosts: [".monkeycode-ai.live"],
    proxy: {
      "/server": {
        target: "http://localhost:5000",
        changeOrigin: true
      },
      "/docs": {
        target: "http://localhost:5000",
        changeOrigin: true
      }
    }
  }
});

Frontend calls /server/login, not http://localhost:5000/server/login.

React Query

All server reads and writes go through TanStack Query. No raw axios.get inside page components.

import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: { retry: 1, refetchOnWindowFocus: false }
  }
});

Query keys

export const keys = {
  employees: (filters) => ["employees", filters],
  employee: (id) => ["employee", id],
  leave: (filters) => ["leave", filters],
  fees: (filters) => ["fees", filters]
};

List query

export function useEmployees(filters) {
  return useQuery({
    queryKey: keys.employees(filters),
    queryFn: () => post("/server/getAllEmployees", filters)
  });
}

Mutation

export function useAddEmployee() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (body) => post("/server/addEmployee", body),
    onSuccess: () => {
      qc.invalidateQueries({ queryKey: ["employees"] });
      toast.success("Employee saved");
    }
  });
}
After create / update / delete, invalidate the matching list key. The table must refresh from React Query, not from local array splicing unless the API returns the new row.

API client

Almost every school API is POST under /server. HR core routes stay under /server/hr. Student app routes stay under /server/student.

export async function post(path, body = {}, files) {
  const hasFiles = Boolean(files);
  let payload;
  let headers = {};

  if (hasFiles) {
    payload = new FormData();
    Object.entries(body || {}).forEach(([k, v]) => payload.append(k, v ?? ""));
    Object.entries(files).forEach(([k, file]) => payload.append(k, file));
  } else {
    headers["Content-Type"] = "application/json";
    payload = JSON.stringify(body);
  }

  const res = await fetch(path, {
    method: "POST",
    headers,
    body: payload
  });
  const data = await res.json();
  if (!res.ok) throw data;
  return data;
}
  • Send JSON for normal forms.
  • Send FormData when the docs mark a file field (img, media, applicant_cv, scanCopy).
  • Read the API docs body tags. Do not guess field names.
  • Store the login token and send it the same way the existing clients do.

DataTable contract

 <DataTable
  columns={columns}
  data={rows}
  loading={isLoading}
  error={error}
  onRowAction={handleAction}
/>
  • columns define header, key, and optional render.
  • Loading uses Skeleton, not a blank page.
  • Empty uses EmptyState.
  • Row actions (edit, approve, delete) come from a dropdown, not three raw buttons per row unless the design needs it.

FormField contract

<FormField label="Employee ID" error={errors.emp_id}>
  <Input value={form.emp_id} onChange={...} />
</FormField>
Do not paste a 200-line JSX form into a page. Split fields into FormSection blocks and reuse the same field components on create and edit.

Page pattern

Each feature page follows the same shape:

  1. PageHeader with title and Add button
  2. FilterBar bound to React Query keys
  3. DataTable from a useQuery
  4. FormDialog for create/edit
  5. ConfirmDialog for delete/approve
export function EmployeesPage() {
  const filters = useFilters();
  const list = useEmployees(filters);
  const save = useAddEmployee();

  return (
    <>
      <PageHeader title="Employees" action="Add employee" onAction={openCreate} />
      <FilterBar value={filters} onChange={setFilters} />
      <DataTable columns={columns} data={list.data} loading={list.isLoading} />
      <EmployeeFormDialog open={open} onSubmit={save.mutate} />
    </>
  );
}

The page wires data. The dialog owns the form. The table owns display.

Forms, files, and POST bodies

  • Field names must match the API docs body list exactly (emp_id, not employeeId).
  • Select options for campus, class, session, department, designation come from their GET/list APIs, not hardcoded arrays.
  • File fields use FileUpload and the shared post(path, body, files) helper.
  • Disabled submit while isPending.

Do and do not

Do
  • Reuse PageHeader, DataTable, FormDialog, FormField, StatusBadge.
  • Keep API functions next to React Query hooks.
  • Match POST paths and body keys from the API docs.
  • Proxy /server through Vite.
  • Invalidate queries after mutations.
Do not
  • Build a new table layout on each page.
  • Call fetch inside a page component.
  • Hardcode the backend host in UI code.
  • Install MUI / Ant Design / Bootstrap beside shadcn.
  • Duplicate create and edit forms as two different files when one dialog can do both.
